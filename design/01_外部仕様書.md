## 1. 製品の目的・利用者

- **目的**：TradingView もトンネルも使わず、**全ローカル**で日経225先物（OSE:NK225M1!・15分足）を自動売買する。司令塔は専用ダッシュボード。
- **利用者**：個人投資家（自分）＋（将来）戦略の配布を受ける購読者。プログラミング知識不要（ダッシュボードと Claude Code 命令書が補完）。
- **戦略の供給元**：StrategyBuilder で作った**完成済み Python 戦略**（MESA ファミリー＝MESA/DT/TSI/CMF/Momentum 等）。戦略は1フォルダで自己完結・ZIP 配布可。

---

## 2. システム境界（外部インターフェース）

```
[ダッシュボード] ──制御/状態──> [ローカルエンジン] ──Webhook(8001)──> [ブリッジ(完成済)] ──> [kabu] ──> 東証
       ▲                              ▲
       │ 成績(BTレポート)             │ tick(TCP5000・ブリッジ→エンジン)
       └──────────────────────────────┘
```

- **入力**：①kabu からの tick（ブリッジ経由・TCP5000）②ローカル蓄積データ（parquet）③外部 CSV（BT 補完）④戦略フォルダ（登録）⑤ユーザー操作（GUI）。
- **出力**：①Webhook（ブリッジへ・有効戦略の注文）②BT 成績レポート（画面）③ログ・状態 LED ④取引記録（全戦略・常時）。
- **ブリッジは別製品・完成済**。エンジンはシグナルを出すだけ。ブリッジが TradingView と同じく**バーに関係なく忠実に発注**（指値含む）。

## 3. ダッシュボードの機能（D10・F1〜F11）

> 当初の中核5機能（F1〜F5）に、ブリッジ制御・モニター（F6/F7）、運用で必要になった機能（F8 取引記録・F9 市場データ管理・F10 市場カレンダー・F11 表示/環境設定）を追加（2026-06-17 時点）。

### F1. 戦略の登録（複数可）＝2段階シーケンス（★ブリッジ登録仕様に整合）

戦略登録は **「① 配布データを取り込む → ② ブリッジへ投げる情報を設定する」** の2段階。②はブリッジ側
戦略レジストリ（`strategies.json`・キー＝`(alertName, interval)`）の仕様に合わせる（webhook-api-spec.md）。

**① 配布データの取り込み**
- 「戦略を追加」→ **Explorer で戦略フォルダを選択**（ZIP 配布物は解凍してそのフォルダを指定）。
- 受け入れ条件：`strategy.py`＋`config.json`＋`manifest.json`＋自己完結部品が揃っていること。
- 取り込み＝`strategies/<フォルダ名>/` にコピー（自己完結）。フォルダ名＝**エンジン内の戦略ID**（内部一意）。

**② ブリッジへ投げる情報（登録フォームで入力）**
- **ショートネーム（`alert_name`）**：ブリッジに送る短い戦略名（例 `DT_Stoch_15m`）。webhook の `alert_name`。既定＝manifest.name。
- **インターバル（`interval`）**：足（分）。既定＝manifest.interval（15）。**ブリッジは `(alert_name, interval)` で戦略を一意識別**するので両方必須。
- **パスフレーズ（`passphrase`）**：webhook 認証。**ブリッジ全体で1つ**（`appsettings.Local.json` の `Webhook.Passphrase` と一致させる）＝エンジンの**グローバル設定**（戦略ごとでない）。全 webhook に付与。
- **説明（`description`）**：任意。**有効（`enabled`/`isEnabled`）**：実行可否（F3・チェックボックス）。

- 記録先＝`registered.json`（`name`=フォルダ名／`alert_name`／`interval`／`enabled`／`description`／`version`／`folder`）＋ `settings.json`（グローバル `passphrase`）。
- **複数戦略を登録可能**。編集（②の再設定）・解除も可（実体は消さず参照を外す）。
- ※ブリッジ側の `strategies.json` 登録はブリッジ UI で行う（本エンジンは webhook に `alert_name`/`interval`/`passphrase` を載せて送るだけ＝D2 webhook 結合のみ。将来オプションで strategies.json 書き出しも検討）。

### F2. パラメータ設定 ＋ 内蔵バックテスト
- **パラメータ GUI**：戦略ごとに `config.json` を**フォーム編集**（数値・真偽・phase 別 6マス等）。Pine の input に対応（例 DT：`rsi_len`/`fib_depth`/`tp1_R`/`allow_long`(6)/`upper_band`(6) 等）。
- **内蔵バックテスト**：パラメータ変更の効果を確かめるため、**ダッシュボード内で BT を実行**できる。
  - 期間＝**半年程度**（直近市場で十分。4年は不要）。
  - データ＝**ローカル蓄積（parquet）を基本**、不足分は**外部 CSV をマージ**（15分足・`N225DataPipeline/csv_input/` 形式）。
  - 成績表示（一般的な項目）：**PF・取引数・勝率・純益・最大DD・平均保有・年/月別内訳・損益曲線**（コスト 0/5/10pt 切替）。
  - 約定モデル＝**TV 忠実（PineBroker・成行=次足始値・指値=イントラバー）**＝golden と同じ。
- フロー：パラメータ編集 → 「バックテスト実行」 → 成績表 → 良ければ確定（config 保存）。

#### F2.1 合成戦略のパラメータ＋自動調整（再最適化）★2026-06-29 追加・汎用
- **合成戦略**（複数のサブ戦略を1戦略に束ねる。例 `MESA5_Portfolio`）は、フォルダ内 `_subs/<名>/` に各サブを同梱する。
  パラメータ画面は **タブ表示**（共通＋サブ別）で `config.json` と各 `_subs/<名>/config.json` を編集する。
- **自動調整（再最適化）＝ボタン1つ**：パラメータ画面の **［🔄 自動調整（再最適化）］**（タブ列右端）を押すと、
  直近1年でグリッド探索＋過適合ガード（train/val・「train 非劣化かつ val 改善」だけ採用）を実行し、
  **old→new の提案表**を出す → **［承認して適用］** で `_subs` の config を更新（自動適用しない＝承認制）。
- **★汎用契約（エンジンは戦略中身を知らない）**：エンジンは戦略固有を一切持たない。
  戦略パッケージが同梱する `optimize.py`（`propose(ctx)` / `apply(ctx, proposals)`）を呼ぶだけ。
  → **新しい合成戦略を作っても、その戦略が自分用 `optimize.py` を同梱するだけで動く＝エンジン無改修・再配布不要**。
  - 実装：`app/engine/reopt.py`（汎用フック）・`app/dashboard/param_form.py`（_subs タブ＋🔄）・`app/dashboard/reopt_dialog.py`（old→new 承認）。
  - `optimize.py` を持たない通常戦略は🔄を出さない（手動調整＋BTのみ）。
- **正本（戦略側のルール）**＝Builder `strategies/_STRUCTURE.md`「合成戦略と自動調整（再最適化）」＋
  各戦略の `design/reoptimization_rule.md`（例 `MESA5_Portfolio`）。**Builder とローカルは相互参照**。

### F3. 戦略ごとの送出可否（「有効」チェックボックス）
- 各戦略の行に**「有効」チェックボックス**。**ON＝発火シグナルをブリッジへ送出／OFF＝記録だけ（送出しない）**。記録は ON/OFF に関係なく常時（F4/F8）。
- 即時反映（再登録不要）。

### F4. 取引記録（全戦略・常時）★dry-run/仮想モードは廃止（2026-06-18）
- **仮想/本番のグローバルモード（dry-run）は廃止**。代わりに**記録を常時・全戦略**で行う（F8）。
- **戦略のオートトレード可否（有効）に関係なく、全登録戦略の発火シグナルを記録**する（理想トレード）。
  - 理由：ブリッジは対等価格の指値で執行するため**実弾が約定しない／価格がずれる**ことがある。記録（理想）と実際の約定を突き合わせる**監査・比較**のため。
- **送出するのは「有効」の戦略のみ**（F5）。無効の戦略は**記録だけ**（送出しない）。記録の `mode` 欄＝有効(送出)＝「本番」／無効(記録のみ)＝「仮想」（フォーマットは従来どおり）。

### F5. 送出制御（戦略ごとの「有効」のみ・自動運用）★起動/停止ボタン廃止
- **オートトレードの起動/停止ボタン・仮想トレード切替は廃止**。**ダッシュボード起動＝自動運用開始**（feed 待受＝記録開始）。
- **送出は戦略一覧の「有効」チェックのみで制御**（ON＝そのバーの発火をブリッジへ送出／OFF＝記録だけ）。即時反映。
- 二重三重の安全：ダッシュボード「有効」＋**ブリッジ側のオートトレードON/OFF・戦略ごと実行ON/OFF**（必ずブリッジと対で使う）。
- **停止手段（専用ボタン無し）**：戦略の「有効」を外す／ブリッジを停止する／ダッシュボードを閉じる。
- 安全：warmup（300本）未充足の戦略は処理待機。市場時間外は発注しない。tick入口(5000)が使用中なら接続せず中止（本番tick経路を壊さない）。

### F6. ブリッジ制御（ダッシュボードで全てコントロール）
- ダッシュボードから**外部ブリッジ（N225BrokerBridge・別製品の C#/WPF アプリ）を起動/停止**する（プロセス起動＝webhook 以外の結合はしない・D1/D2 不変）。
- **運用フロー**：① 戦略登録 → ② カブステーション確認 → ③ **ブリッジ起動（接続）**。自動運用は**ダッシュボード起動と同時に開始**（feed待受＝記録開始）。送出は戦略の「有効」のみ（F5）。
- ブリッジは**[起動]も[停止]も残す**（オートトレード用の起動/停止ボタンは無し）。
- ブリッジ起動＝`subprocess.Popen([exe])`、停止＝`terminate→kill`、実行判定＝`poll()`（既存 `n225_brokerbridge_dashboard.py` を参考）。exe パスは設定（dev 既定＝開発ビルド・配布時はインストール先）。

### F7. 状態モニター（LED）＋ログ
- 稼働モニター LED：**カブStation 実行中／ブリッジ 実行中／オートトレード 実行中／feed**（緑=稼働・灰=停止・3秒毎更新）。
  - カブ＝HTTP `localhost:18080/kabusapi/` ヘルスチェック。ブリッジ＝プロセス `poll()`。**オートトレードLED＝信号チャンネル稼働＝「有効な戦略が1つ以上ある」とき点灯**（＝送出経路が動いている）。feed＝ブリッジから tick 受信中。
- 色分けログ（確定足・板寄せ特別足・シグナル・送出 outcome・エラー）。**セッション限り**（後から振り返るのは F8 取引記録）。
- 各戦略の現在ポジション・直近シグナル・最終足時刻。

### F8. 取引記録（発火ベース・仮想/本番を発生順に累積）
- **記録は「発火」ベース**：戦略が**発火（新規/決済）したイベント**を**発生順**に `app/state/trade_log.jsonl` へ累積。**記録の基準は「発火したか」だけ**＝ブリッジへ送出したか・有効/無効か・建玉化したかに**無関係**（**全戦略・常時**）。`mode` で 本番(有効=注文した)/仮想(無効=記録のみ) を区別・再起動後も残る（F7 ログ欄とは別）。
  - **★再起動は履歴リプレイで復元（TV 同一シーケンス・2026-06-29 改訂）**：起動時に履歴足を live と同一手順で再生し、保有玉・TP/出口・指標を**履歴から再構築**する（持ち越し玉の TP も再起動後そのまま発火＝管理継続）。再生中（ウォームアップ）の発火は記録・発注しない。snapshot/restore（旧仕様）は不要に（建玉 JSON は診断用の受動記録）。詳細＝[`2026-06-29_warmup_replay_session_ohlc_reactivate.md`](2026-06-29_warmup_replay_session_ohlc_reactivate.md)。
- **表示**（下段 [📒 取引記録]）：**2表示＝①記録通り（全イベント時系列・最新上）／②取引一覧（発火のペアリング）**。
  - **取引一覧**＝決済レグの損益・累計は**決済レコード自身の記録値で完結**（決済は entry_ts/建値/損益をすべて自分で持つ。損益が記録されていれば新規との対応有無に関係なく必ず累計に入る）。**新規↔決済のペアリング（完全一致→同戦略90秒近傍の2段照合）は「未決済(open)の残数量算出」だけに使う**／**損益が記録されていない決済のみ「計算不可（損益記録なし）」と理由表示**。
    - ★2026-07-08 改訂：旧仕様（戦略×建値時刻の完全一致ペアリング必須）は、新規の entry_ts＝ライブ受信時刻と再起動 warmup 復元玉由来の決済の entry_ts＝バー時刻が**秒単位で食い違う**と決済が「計算不可」に落ち、累計・合計から漏れた（実害＝2026-07-03 momv2 +125,500円欠落・幽霊未決済1枚）。正本ロジック＝`app/engine/controller.py pair_trades()`（ビューと BT 突合で共有）。
  - 絞り込み＝**戦略ごと（登録 alert_name）＋期間（全期間/当日/今週/今月）**、CSV 書き出し。
- **整理**：**[この戦略の記録を削除]（記録のみ・戦略本体は消えない）／[全削除]**、**登録解除（F1）時に「記録も削除するか」確認**。
- **6ヶ月ローリング・アーカイブ**：起動時に6ヶ月超を `data/history/trade_archive_YYYY-Qn.csv`（四半期）へ自動退避（直近6ヶ月は残す）。[アーカイブを開く] で読み取り閲覧。
- 操作手順は [`../docs/USER_MANUAL.md`](../docs/USER_MANUAL.md) §8.5。

## 4. 入出力フォーマット（外部契約）

### 4.1 Webhook 出力（ブリッジへ・確定仕様）
- 送出先 `POST http://localhost:8001/webhook`、`application/json`。仕様＝[`../../N225BrokerBridge/docs/webhook-api-spec.md`](../../N225BrokerBridge/docs/webhook-api-spec.md) v1.0.0。
- 主要：`alert_name`(=戦略名)・`interval`(**文字列 "15"**)・`strategy.{order_action, market_position, prev_market_position, order_contracts, market_position_size, order_price}`。
- ★**`interval` は文字列で送る**（TradingView と同じ形。ブリッジの受信 DTO が `string?` のため、
  数値で送ると **HTTP 400**）。**エンジン内部は整数のまま**で、送信直前に `str(int(...))` する。
  詳細＝[`03_詳細仕様書.md`](03_詳細仕様書.md) §G.1-b（2026-08-17 の不達事故の記録つき）。
- ポジション遷移（新規/全量返済/部分返済/ドテン）を表す。
- ★**フォーマットは TradingView のアラート本文と同一**（2026-08-18 統一）。キー・並び・型をそろえる：
  `passphrase` / `alert_name` / `time` / `exchange` / `ticker` / `interval` /
  `bar{time,open,high,low,close,volume}` /
  `strategy{position_size, order_action, order_contracts, order_price, order_id,
  market_position, market_position_size, prev_market_position, prev_market_position_size}`。
  `time`・`bar.time` は **UTC・ISO8601（末尾 Z）**＝TradingView の `{{time}}` と同じ形式
  （ローカルの足時刻は日本時間なので変換する）。
  `ticker` は **`NK225M1!`**（TradingView の `{{ticker}}` は**取引所の接頭辞を含まない**＝公式仕様）、
  `exchange` は **`OSE`**。ローソク足はミニのフィードから作るため銘柄はミニ。
  ※「ブリッジが読まない項目だから合わせなくてよい」という判断はしない（ブリッジ側の仕様が
  変われば壊れるため）。
- ★**`order_price` には必ず実際に約定した値段を入れる**（新規・ドテン＝建値／部分返済・全量返済＝
  直近 fill の返済値）。**0 を送ってはならない。** ブリッジのシグナル経路は `order_price` を
  そのまま指値価格として kabu へ渡すため、0 だと「パラメータ不正：値段指定エラー」(4002017) で
  **必ず拒否される**（2026-08-18 13:30 に発生）。対当（最良気配）の値を入れる処理はブリッジの
  **手動発注の経路にしか無い**＝シグナル経路には無い。TradingView は
  `{{strategy.order.price}}` で実値が入るため、この穴を踏まない。

### 4.1-b 銘柄（ticker）の扱い ★現状は簡略化（2026-08-18 明記）

**発注する銘柄を決めているのはブリッジ側**（メイン画面で選択している銘柄）であり、
**webhook の `ticker` は発注銘柄の判断に使われない**（ブリッジの受信 DTO は読むが、
発注時は自身の選択銘柄を使う）。

- 日経225先物には **ラージ／ミニ／マイクロ**がある。
- ローカルエンジンは**ミニのデータフィールドからローソク足を作成**しているため、
  シグナルの銘柄は**日経225ミニ**にあたる。
- 一方、**実際の発注はブリッジ側で固定した銘柄**で行われる。ブリッジ側をマイクロにしておけば、
  ローカル側が銘柄を指定しなくても**マイクロで約定する**。

**本来の姿**は「**ローカル版／TradingView 版から送られた銘柄でブリッジが動作する**」ことだが、
現状は上記のとおり**簡略化**している。将来の課題として、送信元が銘柄を指定する方式に改める。

※ この簡略化はブリッジ操作マニュアル
[`../../N225BrokerBridge/manual/05_advanced/01_webhook_api.md`](../../N225BrokerBridge/manual/05_advanced/01_webhook_api.md)
にも明記している。

## 5. 配布（外部から見た形・D9・D1）

- **戦略**：`<戦略名>/` フォルダを ZIP。受け取る人は解凍 → ダッシュボードの「戦略を追加」で**そのフォルダを Explorer 指定**するだけで登録・実行・BT 可能（自己完結・追加インストール不要）。

## 6. 非機能要件

- **応答性**：15分足。確定足ごとの全戦略処理は数十〜数百ms（次足まで余裕）。リアルタイム指値検知は tick 到着ごとに即時。
- **頑健性**：feed/storage は読込失敗でデータを消さない。warmup ゲート・市場時間ゲート。戦略を無効にすれば注文せず記録だけで安全に観測。warmup は背景実行（起動を待たせない）。
- **決定性**：戦略は独立インスタンス・モジュール可変状態なし＝順次でも並列でも同一結果。
- **可搬性**：自己完結・Windows 10/11・共有 venv（dev）／uv（配布）。
